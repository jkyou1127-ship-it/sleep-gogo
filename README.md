# 슬립 퀘스트 (Sleep Quest)

수면 기록을 게임처럼 관리하는 웹앱. 매일 취침/기상 시각과 컨디션을 기록하면
포인트를 얻고, 포인트로 배지를 모으고 레벨을 올리고, 모은 포인트를 쿠폰으로
발행해서 관리자에게 정산받을 수 있어요.

## 기능

- **로그인 / 회원가입** — Firebase Authentication (이메일 + 비밀번호)
- **오늘의 체크인** — 화면 끈 시각 / 취침 시각 / 기상 시각 / 컨디션(1~5) / 방 온도 / 방 밝기
- **포인트 규칙**
  - 기록 완료(무조건): +10
  - 취침 시각이 22:30 / 23:00 / 24:00 / 01:00 이전: +40 / +30 / +20 / +10
  - 취침 30분 전 화면 끄기: +15
  - 7시간 이상 수면: +10, 8시간 이상 수면: +15
  - 연속 기록 3일 / 7일 / 14일 달성: +20 / +50 / +100
  - 7일 연속 완주 보너스: +50
- **배지 큐브** — 9개 조건 달성 시 배지 획득
- **레벨** — 누적 포인트 300P마다 레벨업
- **데이터 분석** — 취침 시각대별 다음날 컨디션 평균 (3일 이상 기록 시 표시)
- **포인트 → 쿠폰 발행** — 300P = 1,000원, "쿠폰 발행" 버튼을 누르면 코드가 발급됨
- **관리자 페이지** (`sycovy0706@naver.com` 계정 전용)
  - 회원이 보여준 쿠폰 코드를 입력해 **사용 처리**(정산 완료)
  - 전체 쿠폰 목록 확인
  - 회원 목록, 회원별 포인트 지급/차감, 기록 초기화

## 기술 구조

정적 사이트(HTML/CSS/JS, 빌드 과정 없음) + **Firebase**(Authentication,
Firestore)를 백엔드로 사용합니다. 정적 파일은 GitHub Pages에, 데이터와
로그인은 Firebase에 맡기는 구조예요.

```
index.html        메인 앱 화면
login.html        로그인 / 회원가입 화면
admin.html        관리자 전용 화면
css/style.css     스타일
js/firebase.js    Firebase 프로젝트 설정 및 초기화
js/points.js      포인트·배지·레벨·전환 계산 로직 (순수 함수, Firebase와 무관)
js/store.js       Firestore 데이터 읽기/쓰기
js/coupon.js      쿠폰 코드 생성
js/app.js         메인 화면 동작
js/login.js       로그인/회원가입 동작
js/admin.js       관리자 화면 동작
firestore.rules   Firestore 보안 규칙 (실제 접근 제어는 전부 여기서 결정됨)
```

### Firebase 프로젝트 설정 (최초 1회)

1. **Authentication** → **Sign-in method** → **이메일/비밀번호** 제공업체 사용 설정
2. **Firestore Database** 생성 (아직 없다면)
3. **Firestore Database → 규칙(Rules)** 탭에 이 저장소의 `firestore.rules` 내용을
   그대로 붙여넣고 **게시(Publish)**
   - 이 규칙이 실제 보안의 전부입니다. 일반 회원은 자기 자신의 데이터만
     읽고 쓸 수 있고, `sycovy0706@naver.com` 계정으로 로그인한 사람만
     전체 회원/쿠폰을 읽고 관리할 수 있어요.
4. 관리자로 쓸 `sycovy0706@naver.com` 계정도 앱의 회원가입 화면에서 똑같이
   가입하면 돼요 (가입 자체는 누구나 가능하지만, **그 이메일로 로그인했을 때만**
   관리자 페이지 접근이 허용됩니다).

> `js/firebase.js`에 있는 `apiKey`는 비밀값이 아니에요. Firebase 웹 앱의
> 진짜 보안은 `firestore.rules`가 담당하므로, 이 파일을 공개 저장소에
> 커밋해도 안전합니다. (단, Firestore 규칙을 반드시 위 3번처럼 설정해야
> "진짜" 보안이 적용돼요 — 규칙을 안 바꾸면 기본값에 따라 막혀있거나
> 누구나 다 볼 수 있는 상태일 수 있어요.)

### 쿠폰 시스템에 대한 안내

쿠폰 코드는 Firestore에 저장되는 실제 문서라서, 발행한 사람과 다른 기기의
관리자가 코드를 입력하면 정상적으로 조회·사용 처리가 됩니다 (로컬 저장이
아니라 클라우드 DB이기 때문). 다만 코드 자체는 무작위 문자열일 뿐 암호화된
서명은 아니라서, 누군가 Firestore 규칙의 허점을 이용하지 않는 한 위조는
어렵지만 100% 암호학적으로 안전하다고는 볼 수 없어요 — 개인/가족 단위
사용에는 충분한 수준입니다.

관리자가 "사용 처리"하면 그 쿠폰 문서는 **바로 삭제**돼요 (상태만 바꾸는 게
아니라 목록에서 사라짐). 대신 그 금액은 회원 프로필의 누적 "정산 완료"
합계(`settledWon`)에 더해지기 때문에, 각자의 "정산 완료" 총액은 계속 남아있어요.

## 로컬에서 미리보기

의존성 설치 없이 Node.js만 있으면 바로 실행됩니다.

```bash
npm start
# http://localhost:5173 접속
```

Firebase 프로젝트가 위 설정대로 준비되어 있어야 로그인/기록 저장이 정상
동작해요.

## GitHub Pages로 배포하기

이 저장소에는 `main` 브랜치에 push될 때 자동으로 GitHub Pages에 배포하는
GitHub Actions 워크플로우(`.github/workflows/pages.yml`)가 포함되어 있습니다.

1. 저장소 **Settings → Pages** 로 이동
2. **Source**를 **GitHub Actions**로 설정
3. `main` 브랜치에 push하면 자동으로 배포되고, 완료 후 `https://<사용자명>.github.io/<저장소명>/` 에서 접속할 수 있어요.

배포된 도메인(`https://<사용자명>.github.io`)을 Firebase Console →
Authentication → Settings → **승인된 도메인(Authorized domains)** 에 추가해야
로그인이 정상 동작합니다 (`*.github.io` 또는 실제 배포 도메인을 추가하세요).
